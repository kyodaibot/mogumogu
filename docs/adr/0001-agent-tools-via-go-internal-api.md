# Agent 的查询工具通过 Go 内部接口取数，Python 不连数据库

饮食助手的 agent 运行在 Python 服务中，但它的查询工具（get_meals、get_events）不直接访问 PostgreSQL，而是带着 Go 签发的、只对本次请求有效的令牌调用 Go 的内部接口。这样认证、按用户隔离数据和日期跨度校验仍只在 Go 一处实现，Python 不持有数据库凭证；代价是多两个内部接口和一个请求令牌机制。为控制模型调用次数，Go 仍会把默认范围的数据（近 7 天饮食、目标日期前后各 1 天的行程）放进初始上下文，工具只用于查询默认范围以外的数据；曾考虑由 Go 预先传入 30 天数据、工具只在内存中过滤，但这会让每一步的输入 token 变大，模型的“查询”也名不副实，因此未采用。
