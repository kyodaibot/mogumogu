# AI 服务的执行过程连同完整内容交给 Langfuse 日本区域保存

饮食助手的 agent 一条消息要经过多次模型调用和工具调用，只靠每条消息一行、不含内容的 JSON 日志，查不出某一步为什么出错（模型看到了什么、工具参数和结果是什么、校验为什么驳回）。因此 AI 服务把每条消息的执行过程作为一条 trace 发给 Langfuse Cloud 的日本区域（东京），**包含完整内容**：上下文（Profile、过敏原、记忆、饮食记录）、每一步模型的输入和输出、工具参数和结果、搜索关键词，并带上用户 ID（数字）、等级和语言。这改变了原来「默认不记录完整个人资料、饮食内容或模型原始响应」的约定：内容仍不写进 CloudWatch 日志，但交给第三方保存；免费的 Hobby 计划只保留 30 天，到期自动删除。

考虑过的其他做法：LangSmith 与 LangGraph 集成最好，但数据只能放在美国或欧盟，会打破「请求只在日本处理」，免费额度（每月 5,000 条 trace）也不够；Langfuse 自托管需要 ClickHouse 等组件，官方最低配置远超现在的 t4g.micro；只发元数据（节点名、耗时、驳回原因）大部分和现有日志重复，回答不了「为什么」。这是学生个人项目，用户很少，项目所有者接受把内容交给日本境内的第三方以换取调试能力（2026-11-03 决定）；这次不做隐私说明页面，用户变多或公开推广时应补上，或改为只发元数据。

代价：能登录 Langfuse 项目的人可以看到所有用户的饮食和健康信息，账号必须开二步验证，Key 只放在 SSM 和本地 `.env`；SDK 在后台批量发送，Langfuse 不可用或额度用完时只丢 trace，不影响回复。
