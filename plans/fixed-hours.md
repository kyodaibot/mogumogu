# 营业时间改用固定的表

`plans/simplify-hours.md` 的后续。现在每天从官网时间表读取常规营业时间，但这份表不完整：中央食堂、吉田食堂所有日子都没有时间，只能记为「未知」。模型遇到未知的营业时间，会照着菜品的供应时段说「15:00–24:00 营业」。改为在代码里写死各店的营业时间，不再读官网。

## 已确定（2026-11-24 用户确认）

营业时间如下：

| 食堂 | 平日 | 周六 |
|---|---|---|
| 中央食堂 | 8:00–15:15 | 休 |
| 吉田食堂 | 11:00–14:00 | 休 |
| 北部食堂 | 11:00–20:00 | 11:00–14:00 |
| 南部食堂 | 11:00–14:00 | 休 |
| カフェテリア・ルネ | 11:00–21:15 | 11:00–14:00 |
| 桂セレネ | 11:00–14:00、18:00–20:00 | 11:00–14:00 |
| 宇治食堂 | 11:30–14:00、18:00–20:00 | 休 |

- 周日所有食堂都不营业。没写周六时间的店，周六不营业。
- 祝日按平日算，不维护祝日列表。祝日实际休息的店也会被推荐，由卡片上的官网链接兜底。
- 学期中和长假的营业时间不同、临时休业等情况不反映。生协改营业时间时，需要手动改表。

## 要做的改动

1. **后端**：
   - `httpserver/cafeteria_hours.go` 加一张表：店号 → 平日、周六的时段，以及官网营业时间页面的链接（带店铺锚点）；
   - 按就餐日是星期几查表：周日为空，周六用周六时段（没有就为空），其他日子用平日时段；
   - 「平日」分类的判断不再看节假日标记；
   - `store/cafeterias.go` 的查询不再关联 `cafeteria_hours`，不改数据库结构，表先保留。
2. **导入器**（`importer/sources.py`、`jobs.py`）：
   - 删除营业时间的读取和写入（`regular_hours`、`OfficialMenus.hours`、写 `cafeteria_hours` 的部分）；
   - `menu_import_jobs.hours_pending` 列保留，写入 false。
3. **E2E**：E2E 用的是真实日期，周末跑时固定表会让大多数店不营业，卡片就出不来。
   - 仿照质量评测的做法（`clock_cafeteria_eval.go`），加一个只在 E2E 编译标签下生效的文件，把所有店改为每天营业；
   - `e2e/run.sh` 用这个标签编译后端；
   - `e2e/cafeteria.sql` 不再写营业时间。
4. **评测数据**：`ai/evals/cafeteria_menu.sql` 中的营业时间行不再被读取，删除。
5. **文档**：`docs/api.md`、`docs/operations.md`、`docs/project-review.md`，以及 `plans/cafeteria-menus.md`、`plans/simplify-hours.md` 中营业时间来源的描述。
