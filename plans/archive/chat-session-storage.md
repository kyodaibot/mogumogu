# 对话在刷新后保留（sessionStorage）

> 状态：**已完成**（2026-11-02 实施并合并到 dev；刷新后聊天面板保持关着）。

术语见 GLOSSARY.md（对话、对话历史、变更提案、记忆）。

## 目标

现在对话历史只在页面的内存中（`AssistantChat.vue` 的 `turns`）。刷新页面、或从日历切到 Profile 页再回来（聊天组件被卸载），对话就没了。记忆的提示里有「覚えていることを見る」链接，点了再回到日历，对话也会消失。

改为把对话另存一份到浏览器的 sessionStorage：

- 刷新页面、在日历和 Profile 页之间切换后，对话还在，可以接着聊；
- 关闭标签页、点「新しい会話」、退出登录后清空；
- 服务器、AI 服务、数据库都不改；服务器仍然不保存对话。

## 为什么用 sessionStorage，不用 Redis 或数据库（2026-11-02 讨论）

- sessionStorage 在刷新后保留、关闭标签页后清空，最接近现在「一次对话」的含义；每个标签页各一份，不同标签页的对话不会混在一起。
- 不需要新的基础设施，不改变「服务端不保存对话」的隐私约定，改动只在前端。
- Redis 或 PostgreSQL 能做到换设备接着聊、历史可信（不用再把历史当作不可信数据），但要新增服务或数据表、对话 id 的归属检查、保存期限和隐私约定。现在没有这个需求，以后需要时优先在 PostgreSQL 加表（只有一台服务器，用不到 Redis 的多实例共享）。
- project-review 第 8 节「不能用 localStorage 代替 PostgreSQL」指的是用户的业务数据；对话历史本来就不保存在服务器，这里只是让它在同一个标签页里多活一会儿，不违反那条约定。

## 做法

**保存什么**
- 一个键 `mogumogu.chat`，内容为 `{ version, userId, turns, nextId }`。`turns` 就是现在的轮（消息、目标日期、状态、回复、变更提案卡片的状态、已添加的推荐、已撤销的记忆）。
- `turns` 每次变化都整份写入（最多 10 轮，几十 KB 以内）。
- 不保存：输入框里没发出的文字、聊天面板是否打开、正在打开的饮食记录表单。刷新后面板是关着的，打开后看到之前的对话。

**读回时**
- `userId` 与当前登录的用户不同、`version` 不同、或内容无法解析时：丢掉，开始新对话。
- 刷新时还在等待回复的那一轮（`pending`）：显示为失败，可以重试，文案为「回答を受け取る前にページを離れました。もう一度送信してください」（刷新和切换页面都适用）。这条消息可能已经计入额度，重试会再计一次（与现在网络中断时一样）。
- 变更提案卡片正在执行（`running`）时刷新：读回后恢复为未执行。执行可能已经完成，再点「実行」时后端返回 409，卡片显示「已经执行过」并锁定（现有处理）；日历刷新后会显示实际结果。
- 过期的提案照常显示，点「実行」时后端返回 410，卡片已有处理。

**清空**
- 点「新しい会話」；
- 退出登录，以及会话失效（401 后回到登录页）时：在 `session.ts` 的 `logout()` 和 `clear()` 中删除这个键，防止共用电脑时下一个人看到对话；
- 关闭标签页（浏览器自动清空）。

**失败时**
- 隐私模式、存储被禁用或已满时，读写会抛错：都用 try/catch 包住，失败时和现在一样（刷新后对话消失），不影响聊天本身。

**不变**
- 历史仍然由浏览器发给服务器，仍然视为不可信数据；Go 和 AI 服务的检查、过敏原以 Profile 为准等都不变。
- 10 轮上限不变。

## 实施

分支 `feat/chat-session-storage`，一个里程碑：

1. 前端：新增 `lib/chatStore.ts`（读、写、清空，带 `userId` 和 `version` 检查，以及读回时把 `pending` 和 `running` 复原）；`AssistantChat.vue` 启动时读回、变化时写入、「新しい会話」时清空；`session.ts` 退出和失效时清空；i18n 新增一条文案。
2. 测试：
   - Vitest：`chatStore` 的读写；用户不同、版本不同、内容损坏时丢掉；`pending` 变成可重试的失败；`running` 复原；存储抛错时不报错。
   - E2E：把现在的「刷新后开始新对话」改为「刷新后对话还在，接着发一条消息时带着之前的历史」；「新しい会話」后刷新仍是空的；退出再登录后是空的。
3. 文档：GLOSSARY.md「对话」「对话历史」中「刷新页面后开始新的对话」改为「关闭标签页后结束」；docs/project-review.md 3.6 同样修改；plans/archive/phase-4b.md 不改（当时的决定）。

## 验收标准

1. 发两条消息后刷新页面，打开聊天面板能看到这两轮；再发一条，请求中的 `history` 有 2 轮。
2. 从日历切到 Profile 页再回来，对话还在。
3. 「新しい会話」、退出登录后再登录（同一个或另一个账号），对话是空的。
4. 等待回复时刷新，那一轮显示为可以重试的失败。
5. `make test`、`make test-e2e` 通过。

## 实施结果（2026-11-02）

- `make test`（Vitest 53 项，新增 6 项）和 `make test-e2e`（58 项，新增 4 项）通过；后端和 AI 服务没有改动。
- 与计划的差异：「新しい会話」不单独删除存储，而是和其他变化一样把空的对话写进去，效果相同。刷新或切换页面时正在等待回复的那一轮，文案改为「回答を受け取る前にページを離れました。もう一度送信してください。」，两种情况都适用。
- E2E 中原来的「刷新后开始新对话」改为：刷新后面板关着、打开后对话还在、下一条消息带着之前的 3 轮历史；「新しい会話」之后刷新仍然是空的；从 Profile 页回到日历后对话还在；退出再登录后第一条消息没有历史。

## 不在范围内

- 换设备继续对话、服务器保存对话（Redis、PostgreSQL）；
- 多个标签页之间共享对话；
- 保存输入框中的草稿、面板的打开状态。
