# 界面多语言：日语和英语

> 状态：**已确认**（2026-10-28）。分支 `feat/ja`，按里程碑逐个实施。

## 背景
目前 mogumogu 的界面文案、日期格式和 AI 助手的回答都只有中文。今后产品只支持**日语和英语**。中文界面整个移除，开发文档仍然用中文。

已确认的决定：
- **界面语言**：第一次访问时，浏览器语言是日语就显示日语，其他情况一律显示英语。页头有「日本語 / English」切换按钮，用户的选择保存在 localStorage。不改动数据库。
- **AI 回答语言**：跟随界面语言。前端把 `locale`（`ja` 或 `en`）发给后端，后端再转给 AI 服务。
- **实现方式**：自己写一个轻量字典，不引入 vue-i18n。日期显示用 `Intl`。
- **文档**：README 改成英语；`docs/` 和 `plans/` 继续用中文，只同步修改其中涉及语言的约定。

开工前先从 dev 切出 `feat/ja`，并新建 `plans/i18n.md`（中文，内容就是本计划），作为这次授权的范围（AGENTS.md 的要求）。

用户自己输入的自由文本（行程标题、饮食内容、过敏原）不翻译，也不迁移旧数据：输入什么就保存什么。

## 里程碑 1：前端 i18n

**新增 `frontend/src/i18n/`**
- `en.ts`：全部文案。它的类型就是字典结构，作为基准。
- `ja.ts`：类型声明为 `Messages`（与 `typeof en` 相同）。缺了某个键或类型不对时，`vue-tsc` 构建会报错，这样能防止漏翻译。
- `index.ts`：
  - `locale` 是一个 ref，值为 `'ja' | 'en'`；
  - `t(key, params)` 用点号路径取文案，`{name}` 形式的占位符会被替换；
  - `setLocale()` 负责写入 localStorage（读写都用 try/catch 包住），同时设置 `document.documentElement.lang`；
  - `detectLocale()` 的顺序：先看 localStorage，再看 `navigator.languages` 里是否有以 `ja` 开头的，否则用 `en`。

**替换各处硬编码的文案**（总共约 200 条，具体位置见探索结果）：
- 页面和组件：`App.vue`、`pages/LoginPage.vue`、`pages/CalendarPage.vue`、`pages/ProfilePage.vue`、`components/AssistantChat.vue`、`EventForm.vue`、`MealForm.vue`、`MonthPicker.vue`。
- `lib/messages.ts`：错误码、校验原因（reason）和字段对应的文案改为从字典读取。逻辑保持不变：后端返回的 `message` 仍然只给开发者看，前端不显示。
- `lib/meals.ts`：餐次名称和营养素名称，以及「未填写」，都改为从字典读取。`lib/assistant.ts` 里重复的那份餐次名称删掉，直接复用 `meals.ts`。
- `lib/assistant.ts`：预设问题和「今天 / 明天 / 某月某日」按语言生成，用户点击后把这段文字原样发给 AI。
- `index.html`：去掉 `lang="zh-CN"`，改由 `setLocale()` 在运行时设置。

**日期**（`lib/date.ts`、`MonthPicker.vue`）
- 删掉手写的星期数组和「年」「月」，改用 `Intl.DateTimeFormat(locale, { timeZone: 'Asia/Tokyo', ... })` 生成。例如 ja 显示为「10月23日(金)」「2026年10月」，en 显示为「Fri, Oct 23」「October 2026」。
- 日期的计算部分（`en-CA` 的 YYYY-MM-DD）保持不变。
- 每周仍然从周一开始，两种语言相同。

**语言切换**
- 在 `App.vue` 的导航栏和登录页各放一个小切换按钮。切换后立即生效，不需要刷新页面。
- 过敏原在保存时，切分规则原本就支持 `,`、`，`、`、`；显示时的分隔符按语言决定，ja 用「、」，en 用「, 」。

**测试**
- Vitest：`date.test.ts` 和 `assistant.test.ts` 改为两种语言各断言一次。新增 `i18n.test.ts`，覆盖 `detectLocale`（localStorage 优先，`ja-JP` 判为 ja，`fr` 判为 en）和 `t()` 的占位符替换。
- E2E（`e2e/browser.mjs`）：
  - 启动 Chrome 时加上 `--lang=ja`，主流程用日语跑，把原来所有中文选择器和断言都换成日语；
  - 最后加一段：切换到 English，检查导航、星期标题和预设问题都变成英语，刷新后仍然是英语。
  - 测试里输入的自由文本数据改成日语，例如「ピーナッツ、えび」。

## 里程碑 2：AI 跟随界面语言

**API**（`docs/api.md`）
- `POST /api/assistant/messages` 的请求体新增可选字段 `locale`，取值为 `"ja"` 或 `"en"`，省略时按 `en` 处理。其他值返回 `validation_failed`，原因是 `invalid_value`。
- 前端 `api/index.ts` 中的 `sendAssistantMessage` 带上当前语言。

**后端**
- `handlers_assistant.go`：校验 `locale`，并把它写进 `Context`。
- `internal/assistant/client.go`：`Context` 新增字段 `Locale string \`json:"locale"\``。
- 测试：在 `assistant_integration_test.go` 里加用例，覆盖传递 `locale`、省略时为 `en`、非法值返回 422。

**AI 服务**（`ai/src/mogumogu_ai/`）
- `schemas.py`：`Context.locale: Literal["ja", "en"] = "en"`。
- `prompt.py`：系统提示改写成**英文**，规则逐条保持原意。加一句「Reply in the language of `context.locale` (ja = Japanese, en = English)」。这句话不随请求变化，所以系统提示仍然是固定内容，可以缓存。原来的中文例句改成英文。
- 字数上限：英文比中文长，所以放宽为 name ≤ 80、description 和 reason ≤ 200、reply ≤ 1000。前端只是显示文字，不需要改。
- 以下文字都改成英文：工具描述（`tools.py`）、交给模型的反馈和错误信息（`agent.py`、`tools.py`），以及 schema 的字段描述和校验错误（`schemas.py`）。
- 过敏原检查（`agent.py`）仍然用子串匹配。它的局限要写进文档：用户输入的过敏原语言和回答语言不同时，这个检查无法发现问题，这时只能依靠系统提示里的规则。
- 假模型（`demo.py`）：用日语和英语的关键词判断问题类型（「何を食べ」「what should I eat」，以及朝食、昼食、夕食和 breakfast、lunch、dinner），按 `context.locale` 用对应语言回答。
- 测试（`ai/tests/`）：把中文断言换成新的英文反馈文字；固定测试数据改成日语。新增用例，验证 `locale` 能被正确解析和传入。
- 评估（`ai/evals/run_evals.py`）：用例改为日语为主，另加 1 到 2 个英语用例。过敏原关键词列表改为えび、エビ、海老、shrimp、ピーナッツ、peanut。

## 验证
- 每个里程碑：`make test`（vue-tsc 会检查两份字典是否一致）、`make test-integration`、`make test-e2e`（日语主流程和英语切换）。
- 里程碑 2 运行 `make ai-eval`：用真实模型跑 ja 和 en 用例，确认回答语言正确、推荐中不含过敏原。这一步每次要花几美分。
- 浏览器手动检查：用 `make dev` 启动，分别用日语和英语浏览器打开，确认自动选择正确、切换后刷新仍然保持、日期格式正确。在 375px 宽度下检查英文较长的按钮和标签有没有被挤坏。
- 合并到 master 后会自动部署。部署后在线上检查一次 `/api/health/ready`，再分别用两种语言问一次 AI 助手。
